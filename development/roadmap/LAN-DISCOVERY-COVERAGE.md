# Independent LAN discovery and DNS evidence

The Engine owns a bounded, ephemeral observation store. LAN discovery does not depend on Engine DNS traffic or router authentication. WPF owns registration/metadata/policy; Monitor only consumes read-only diagnostics.

Providers currently include local OS addresses/hostname and Linux kernel ARP/NDP evidence. Observations carry interface, address, MAC when available, provider provenance/time, neighbour state and private-MAC possibility. Locally administered MAC means randomization is possible, not proven. Cache presence is not proof that a device is online. Hostname and IP are metadata/bindings, never physical identity.

Internally generated observation UUIDs are stable within the retained Engine session. They are explicitly provisional and separate from policy DeviceId. Same-MAC observations correlate across IPv4/IPv6 only within the same observed interface; conflicting address evidence is retained and ambiguous DNS attribution withheld. No automatic policy binding, registration or alias is written. Expiry/restart/randomized MAC can break provisional correlation; physical continuity requires stronger evidence/cooperation.

Retention remains memory-only: at most 64 LAN observation identities, eight evidence entries each and ten minutes without an observation. DNS remains the existing separate 64-source/ten-minute aggregate pipeline. No raw query/domain retention is added. Passive reads are cached for 15 seconds; neighbour subprocess input is capped at 64 KiB and execution at one second. Provider unavailability is a visibility limitation, not an empty-LAN guarantee.

Authenticated GET `/v2/discovery` exposes observations. Authenticated POST `/v2/discovery/refresh` with `{}` is an explicit local echo refresh, globally limited to once per minute, 16 concurrent IPv4 probes, 180 ms each, at most 254 targets from actual connected /24–/30 interfaces and a six-second deadline. Larger subnets remain passive-only rather than inventing a /24. At most two connected IPv6 interfaces receive one ordinary scoped all-nodes echo; clients may not answer. No port scan, router login, DNS lookup, network configuration or policy mutation. No active discovery occurs merely from Monitor polling. Echo/NDP availability and Wi-Fi isolation constrain discovery; absence of a response is not absence of a device.

WPF Scan devices requests this refresh and consumes independent Engine evidence. Monitor keeps a compact, independently scrollable list/detail model and correlates observations with existing DNS counters without its own identity database. LAN presence, identity confidence, DNS activity, coverage and resolver path are separate concepts. A LAN device with zero Engine DNS remains visible and Unknown for coverage. Existing rate-controlled discovery notifications remain; no notification is generated simply because an idle device has no DNS traffic.

Configuration is intent, observed DNS is interval-scoped use, and neither proves exclusive coverage. The legacy advertisement/readiness evaluator no longer emits COMPLETE. Unique observed Engine use provides PARTIAL evidence; no matched use gives UNKNOWN, never BYPASS. Router/client providers can later enrich this model with independently timestamped evidence; no vendor adapter is prerequisite. No currently exposed provider can justify complete coverage.

Acceptance requires automatic real-LAN observations without seeding externally supplied IP/MAC/hostname data. Resolver choice may remain UNKNOWN even when presence is observed. IPv6 addresses are diagnostic evidence; existing IPv4-only policy identity binding is not silently extended by this feature.

Local Monitor publication retains the existing 128 KiB ceiling. If the combined payload exceeds that limit, it explicitly reports omitted LAN evidence/rows; Monitor withholds attribution from truncated evidence. HTTPS discovery retains the bounded full observation view. Provider I/O is outside the DNS counter lock.
